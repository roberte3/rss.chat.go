# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

A Go port of Dave Winer's [RSS.Chat](https://github.com/scripting/rss.chat), intended as an
open-source release and as the backend for glurpglurp.app (not yet launched).

Fidelity to the original matters. When behaviour is ambiguous, the JS implementation is the
specification — several subtle bugs here came from diverging from it unintentionally. The
reference is gitignored, so clone it separately when you need it:

    git clone https://github.com/scripting/rss.chat /tmp/rss.chat
    # server/code/rssnetwork.js is the file worth reading

## Commands

    go build ./...                       # build
    go run . -setup                      # create config.json, databases, settings, blocklist
    go run .                             # run (requires config.json)
    go test ./...                        # full suite (~139 tests, 10 packages)
    go test -race ./...                  # what CI runs; always check before pushing
    go test ./api/ -run TestDeletePost -v # single test
    gofmt -l .                           # must be empty; CI fails otherwise
    make build                           # -> ./rss-chat

CI (`.github/workflows/ci.yml`) runs build, vet, `test -race` on Ubuntu and macOS, plus a
`gofmt`/`go mod tidy` job. Run `go build && go vet && gofmt -l . && go test -race ./...`
locally before pushing — the whole suite has silently gone red before.

`config.json`, `settings.json`, `blocklist.json`, the `*.db` files and `feeds/` are all
gitignored and generated by `-setup`. A fresh clone has none of them.

## Architecture

Request flow: `main.go` wires config → db → `publish.Publisher` → `api.Handler` → mux, with
`client.Server` last on `/` as a catch-all.

### BaseURL includes the scheme

`feed.BuilderConfig.BaseURL` comes from `config.myDomain` and **already contains
`http://` or `https://`, with no trailing slash**. Never prepend a scheme to it. Doing so both
double-prefixes the result and forces `http://` on an HTTPS deployment.

This matters more than it sounds: items store an absolute `feedUrl`, and per-user feed reads
match on it exactly (`where items.feedUrl = ?`). Build that URL differently in the writer and
the reader and lookups silently return nothing — no error, just empty feeds.

### Two storage modes, and feeds served two ways

`flFeedsInDatabase` selects filesystem (default) or database storage for generated feeds.
Not everything respects it — `PublishCommentsFeed` always writes to disk, unlike the user,
global and OPML publishers which call `db.StoreFeed` in database mode.

Serving is deliberately split:

- **User and everyone feeds** are served from what was published, so nothing serves them
  until something writes them. `/createnewuser` publishes the new user's feed, and
  `BackfillMissingFeeds` fills in anyone missing one at startup, in both storage modes — so
  in a running server a user has a feed from the moment the account exists. A user inserted
  straight into the database, which is what `insertTestUser` does, has no feed until
  something publishes one: tests that read `/feed` for such a user must publish first.
- **Subscription list (OPML) and comments feeds** are built from the database per request.
  They were previously served from published artifacts and 404'd permanently in the default
  configuration; generating them per request is what fixes that. Keep it that way.

### Routes are mirrored, and wildcards are whole segments

`RegisterRoutes` registers every endpoint at both `/x` and `/api/x` via its `register` helper.

`net/http` requires a pattern wildcard to span a complete path segment. `"{id}.xml"` **panics
at registration** — a startup crash, not a 404. That is why the comments feed route is
`/comments/{screenname}/{file}` with the extension stripped in the handler.

### Deletion is soft

`flDeleted` marks a post deleted; the row stays so permalinks keep resolving. Every read query
filters `flDeleted is null or flDeleted = 0` — except `GetItemByID`, which returns the row and
leaves the check to the caller. Anything new that reads items must filter it.

### Authentication

`emailSecret` is a permanent bearer token, sent as `emailaddress` + `emailcode` **query
parameters on every request, including POSTs** — that is how the bundled client works.
Switching handlers to `PostFormValue` breaks every write from the UI. It cannot be tightened
without forking the vendored client; see the Security model section of README.md for the full
picture and the mitigations in place.

Things not to undo: the secret is compared with `crypto/subtle`, is `json:"-"` so it can never
be serialized into a response, and the mail-sending endpoints are rate-limited per mailbox and
per source address (`api/ratelimit.go`). `clientIP` ignores `X-Forwarded-For` on purpose.

### The web client is vendored, not ours

`client/code/` is Dave Winer's client, MIT, **byte-for-byte upstream with no local changes** —
see `client/code/README-VENDORED.md` for the pinned commit and re-sync steps. Don't edit it.
If the server needs different behaviour, add a macro on the Go side or send the change upstream.

`client/client.go` substitutes `[%macro%]` placeholders in `index.html` only. Every macro the
HTML references must exist in `substituteConfig`, or the raw placeholder is served into the
page with no error. `TestVendoredClientMacrosAreSatisfied` guards this and is the test most
likely to catch a bad re-sync.

### Database

Schema lives in `db.CreateTables` (`db/db.go`) — read it there rather than trusting a copy.
Two SQLite files: the main database and a separate media database, both via `modernc.org/sqlite`
(pure Go, no CGO). WAL mode, foreign keys on, 5s busy timeout applied at open.

Note `items.author` holds the screenname; there is no `screenname` column on `items`, and
`Item.Author` in Go is the *display* name (feed title if set), which is a different thing from
`Item.Screenname`.

## Testing

Helpers in `api/endpoint_test.go`: `setupTestServer(t)` returns `(mux, conn, handler)`;
`setupTestServerWithFeedsDB(t)` adds a feeds database; `insertTestUser(t, conn, name, secret)`
creates a user whose secret doubles as the auth code; `authedPost(mux, path, name, secret, form)`
issues an authenticated write.

Two traps that have produced falsely-passing tests here:

- Asserting a *substring is absent* from a response that 404s passes for the wrong reason.
  Assert the positive case too, or check the status.
- Filesystem-mode feeds must be published before they can be read. `insertTestUser` writes
  the row directly and publishes nothing, so a user it creates has no feed yet.

When fixing a bug, confirm the new test fails against the old behaviour before committing.

## Known gaps

- `websocketPort` (1462) is config-only — **nothing listens on it**. `/subscribe` and `/ws` are
  served on the main HTTP port, but the client is handed `ws://localhost:1462/` via
  `urlWebsocketServerForClient`, so in-browser real-time updates connect to a dead address.
- `/version` is called by the client's debug helpers but not implemented.
- `IsUserAdmin` always returns false, as in the original.
- `/readhttpfile` is not implemented, so the client's Scripts menu cannot work. `urlMenuOpml`
  is wired through to `[%urlMenuOpml%]` and defaults to empty, which is how the client is
  told there is no menu — leave it empty and nothing calls the endpoint. Setting it without
  implementing `/readhttpfile` is not fatal: the fetch fails and `startScriptsMenus` logs to
  the console, so the menu simply never appears.

  Upstream's version takes a `url` parameter and returns whatever it fetches, with no
  authentication, scheme check, host check or size limit — an unauthenticated SSRF that would
  let any caller use the server to reach cloud metadata endpoints and private-network hosts.
  Porting it faithfully is the one place where following `rssnetwork.js` is the wrong call.
  If it gets built, it needs http/https only, resolved addresses checked against loopback,
  private and link-local ranges, revalidation on every redirect hop, plus size and time caps.
